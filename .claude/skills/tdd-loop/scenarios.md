# 1. 시나리오 — 무엇을 검사할 것인가를 먼저 소유한다

주 대화가 한다. 코드 전이다. 산출물은 **티켓 코멘트 하나**(target 마다) — 시그니처 절 + 시나리오 표 + AC 커버리지 표 — 이고, 사람이 그것을 승인하는 순간이 "무엇을 검사할 것인가" 의 소유 시점이다.

## 1. 시그니처 — 이름과 형태를 먼저 고정한다

테스트가 부를 것의 **이름 · 파라미터 · 반환 · 오류**를 정한다. 구현이 아니다 — 본문은 없다. 기존 코드의 관례(동사 · 타입 · 오류 방식)를 읽고 그대로 따른다; 신조어를 만들지 않는다.

네 요소를 빠짐없이 — 해당 없으면 "없음" 으로 적는다(빈칸과 다르다):

| 요소 | 무엇 |
|---|---|
| **타입** | 새 타입 · 기존 타입에 더하는 필드 |
| **함수 / API / CLI** | 시그니처 — `def f(a: str, *, limit: int = 10) -> Result` · `GET /notes?tag=` · `obs promql --labels` |
| **오류 케이스** | 어떤 입력에서 무엇을 던지나 — **그리고 무엇을 조용히 무시하나(no-op)**. 던지지 않는 것도 결정이다. 예외 시나리오의 원천이 여기다 |
| **인터페이스** (프론트 Props · CLI 플래그 · 응답 형태) | 밖에서 보이는 형태 |

시그니처가 여럿이면 **각각 블록**으로 — 시나리오도 그 아래 붙는다(§3). 기존 시그니처를 **바꾸는** 것이면 그 사실과 호출자를 적는다 — red 의 stub 범위가 거기까지 넓어진다.

## 1.5 층 — 시나리오는 그 층이 더한 것에 붙는다

변경이 여러 층을 지나면(파서 → 조립 → CLI · 도메인 → 서비스 → 컨트롤러) **층마다 진입점 하나 = 블록 하나**, 블록 첫 줄에 **더하는 것** — 아래 층 대비 이 층이 새로 하는 일 한 줄.

| 역할 | 더하는 것 | 예 |
|---|---|---|
| **계산 · 도메인** | 값 · 규칙 · 예외 | `parse_metric` · `SeparateIds` · 엔티티 규칙 |
| **변환** | 모양 · 직렬화 | `*_lines` · `convertSourceDetail` · DTO |
| **조립** | 배선 · 순서 · 호출 수 · 오류 전파 | `promql_run` · `FindNewJobPostingApp.Run` · 서비스 |
| **경계 — 진입** | 입력 파싱 · exit / 상태코드 | `promql_main` · `main` · 컨트롤러 |
| **경계 — 외부 호출** | 프로토콜 · 실 응답의 형태 | `Client` · `wanted.List` · 리포지토리 |

- 한 주장은 **가장 낮은 층 하나**에. 위 층은 아래 층의 경우들을 **다시 열거하지 않는다** — 배선이 보이는 최소 예 하나뿐. 아래가 바뀔 때 둘이 깨지면 중복이다.
- 판별: Then 을 확인하는 데 **협력자의 대역**(인터페이스 구현체)이 필요 없으면 조립 시나리오가 아니고, **프로세스 경계**(argv · env · stdout · HTTP · gRPC 메시지)가 필요 없으면 경계 시나리오가 아니다 — 한 층 내린다.
- 파일 배치(디렉터리 · 티어)는 저장소 규칙이 정한다. 이 스킬은 **어느 층이 어떤 주장을 소유하나**만.

## 2. 시나리오 — Given / When / Then

시그니처의 각 항목마다 **정상 · 경계 · 예외**를 뽑는다. 한 행 = 한 주장. 형식은 GWT — 세 칸이 나중에 테스트 코드의 세 부분이 된다.

| 종류 | 뜻 |
|---|---|
| **정상** | 행복 경로 — 일반 입력의 기대 동작 |
| **경계** | 상한 · 하한 · 빈 것 · 하나 · 같은 값 · 마지막 요소 |
| **예외** | 잘못된 입력 · 외부 실패 · **무시돼야 할 입력**(시그니처의 no-op) |
| **가드** | 이미 되는 동작이 **유지된다** — Bug 티켓의 회귀 방지 · 시그니처 변경 뒤 호출자. **red 에서 통과가 기대되는 유일한 종류**다. 승인된 행만 |

- **AC 항목마다** 최소 하나. 한 AC 가 여러 행을 낳는 것이 보통이다.
- **AC 밖도 더한다**(출처 `추가`) — 경계값 · 빈 입력 · 예외 처리는 같은 약속의 가장자리다. 코드를 읽어야 보인다.
- **새 동작은 더하지 않는다** — AC 에 없는 기능은 범위 확장이다. CLAUDE.md §3.
- **이미 있는 테스트가 덮는 행**은 출처를 `기존: test_…` 로 적고 red 에서 쓰지 않는다.
- **Bug 티켓의 첫 행은 언제나 재현**이다 — 버그의 입력(Given · When)에 기대 동작(Then)을 단언한다. red 에서 실패해야 재현된 것이다. 그다음 행들이 `가드`(고치면서 깨지면 안 되는 것)다.

## 3. 형식 — 시그니처마다, 종류마다

한 표에 다 뭉치지 않는다. **시그니처 하나 = 블록 하나**, 그 안에서 **종류(정상 · 경계 · 예외 · 가드)마다 작은 표**. 비는 종류는 생략한다. 번호는 코멘트 전체 통번호 — AC 커버리지 표가 가리킨다.

````markdown
### TDD 시나리오 — <target repo>

#### 타입
- `Note.tags: list[str]` (추가)

---

#### `parse(text: str) -> Doc`
- 오류: `parse("")` → `ValueError`
- 인터페이스: 없음

**정상**

| # | Given | When | Then | 출처 | 테스트 이름 | 티어 | 의존성 |
|---|---|---|---|---|---|---|---|
| 1 | 한 문단짜리 텍스트 | `parse(text)` | `Doc` 하나, 문단 하나 | AC-1 | `test_parse_single_paragraph` | 단위 | — |

**경계**

| # | Given | When | Then | 출처 | 테스트 이름 | 티어 | 의존성 |
|---|---|---|---|---|---|---|---|
| 2 | 공백만 있는 문자열 | `parse("   ")` | `ValueError` | 추가 | `test_parse_rejects_whitespace_only` | 단위 | — |

**예외**

| # | Given | When | Then | 출처 | 테스트 이름 | 티어 | 의존성 |
|---|---|---|---|---|---|---|---|
| 3 | 빈 문자열 | `parse("")` | `ValueError` | AC-1 | `test_parse_rejects_empty` | 단위 | — |

---

#### `Config.load(config_dir: Path | None = None) -> Config`
- 오류: 파일이 없으면 **무시하고 기본값**(no-op) · 파일이 깨졌으면 `ConfigError`
- 인터페이스: env `OBS_TOKEN` 이 파일보다 우선

**정상**

| # | Given | When | Then | 출처 | 테스트 이름 | 티어 | 의존성 |
|---|---|---|---|---|---|---|---|
| 4 | env 에 토큰 · 파일에도 토큰 | `Config.load()` | env 의 값이 이긴다 | AC-2 | `test_token_env_beats_file` | 단위 | fake(env) |

**가드**

| # | Given | When | Then | 출처 | 테스트 이름 | 티어 | 의존성 |
|---|---|---|---|---|---|---|---|
| 5 | 태그 없는 기존 설정 파일 | `Config.load()` | 지금처럼 읽힌다 | AC-3 | `test_legacy_config_still_loads` | 단위 | fake |

---

---

#### `promql_run(client: Client, a: PromqlArgs, at: float | None = None) -> RunResult`
- 더하는 것: `--range` → 창 · 자동 step · `query_range` 호출. stdout 없음
- 오류: 질의 없음 → `ObsError`, 요청 전

**정상**

| # | Given | When | Then | 출처 | 테스트 이름 | 티어 | 의존성 |
|---|---|---|---|---|---|---|---|
| 6 | `range_="30m"` | `promql_run(client, a, at=AT)` | `query_range` 를 1회, `step=30s` 로 부른다 | AC-4 | `test_promql_range_window_and_auto_step` | 단위 | fake(transport) |

**예외**

| # | Given | When | Then | 출처 | 테스트 이름 | 티어 | 의존성 |
|---|---|---|---|---|---|---|---|
| 7 | 질의 없음 | `promql_run(client, PromqlArgs())` | `ObsError` · 요청 0회 | AC-4 | `test_promql_requires_query` | 단위 | fake(transport) |

---

#### `promql_main(argv: Sequence[str] | None = None) -> None`
- 더하는 것: argv → `PromqlArgs` · `--json` · exit 코드. 창 · step 은 다시 세지 않는다(6 의 것)

**정상**

| # | Given | When | Then | 출처 | 테스트 이름 | 티어 | 의존성 |
|---|---|---|---|---|---|---|---|
| 8 | `["up", "--range", "30m"]` | `promql_main(argv)` | `promql_run` 에 `range_="30m"` 이 들어간다 | AC-4 | `test_promql_main_passes_range` | 단위 | fake(run) |

티어 · 의존성 — <왜 이렇게 골랐나, 한두 줄>

#### AC 커버리지

| AC | 시나리오 # |
|---|---|
| AC-1 빈 입력을 거부한다 | 1, 3 |
| AC-2 토큰은 env 우선 | 4 |
| AC-3 기존 설정은 깨지지 않는다 | 5 |
| AC-4 `--range` 는 구간 조회다 | 6, 7, 8 |
````

| 자리 | 규칙 |
|---|---|
| 타입 | 시그니처들이 공유하는 것 — 위에 한 번. 없으면 절을 생략 |
| 시그니처 블록 | 선언 한 줄이 제목. 그 아래 **더하는 것**(층이 여럿일 때 · §1.5) · **오류 케이스**(던지는 것 + no-op) · **인터페이스**. 그다음 종류별 표 |
| Given | 전제 — 상태 · 입력 · 외부의 응답. 픽스처의 우연("65줄")이 아니라 성질("스트림 둘") |
| When | 한 번의 호출 — 시그니처의 이름 그대로 |
| Then | 한 주장 — 성질("없다" · "거부한다" · "1회다"). "그리고" 가 들어가면 두 행 |
| 테스트 이름 | 저장소 규약대로. red 에서 **이 이름 그대로**. verifier 가 이 이름으로 대조한다 |
| 티어 · 의존성 | 이 티켓의 검수용이 아니다 — 아직 정해지지 않은 테스트 정책의 **증거**. 왜 를 끝에 한두 줄로 |
| AC 커버리지 | **모든 AC 가 한 행 이상**. 비는 AC 가 있으면 시나리오를 더하거나, AC 가 테스트로 못 잡는 것이면 그 사실을 적고 사람에게 |

## 4. 게시

```bash
gh issue comment <N> -R jyoliar-lab/ops-workflow --body-file tmp/github-issues/<N>-scenarios-<repo>.md
```

출력의 코멘트 URL 에서 **`<id>`(`#issuecomment-<id>`)를 기록**한다 — 수정은 이 ID 로만.

착수 요약의 계획과 표가 어긋나면 그 차이를 코멘트 위에 한 줄.

## 5. 멈춘다 — 승인

게시했으면 **멈추고 기다린다.** 사람이 시그니처 · 시나리오 · AC 커버리지를 한 번에 본다. "승인" 이 오면 [red.md](red.md).

- **수정 요청** → 새 코멘트가 아니라 기록한 ID 로 **지정 수정**:
  ```bash
  gh api -X PATCH repos/jyoliar-lab/ops-workflow/issues/comments/<id> -f body="$(cat tmp/github-issues/<N>-scenarios-<repo>.md)"
  ```
  다시 기다린다. "좋아요" 한마디로 남은 지적을 건너뛰지 않는다 — 명시적 승인까지.
- **"추가" 행이 범위 밖** → 지운다. 필요하다고 보면 이유를 말하되 판정은 사람의 것.
- **판정 자체가 뒤집히면**(비대상) 스킬을 나간다 — 표는 남긴다.

## 흔한 실수

- **시나리오가 구현을 말한다** — "캐시에 저장한다" 는 구현이다. 밖에서 보이는 약속: "두 번째 호출은 요청을 보내지 않는다".
- **한 행에 두 주장** — "거부하고 로그를 남긴다" 는 두 행.
- **Given 에 픽스처 값** — "65줄을 돌려준다" 는 재녹화에 깨진다. "스트림 수만큼" 이 약속.
- **AC 6개 중 5개만** — 커버리지 표를 채우면 보인다. 표 없이 넘어가지 않는다.
- **Given 을 손으로 만들 수 없다** — "실 사이트의 지금 공고" · "실 DB 의 행" 은 Given 이 아니다. 층이 틀렸거나 대역이 없는 것 — 의존성 열에 `실 API` 로 적고 승인 때 사람이 본다.
- **위 층이 아래 층의 경우를 다시 센다** — `Run` 테스트가 "전부 새것 · 전부 저장됨 · 섞임" 을 다시 돌면 `SeparateIds` 의 표를 복사한 것. 배선 예 하나로 줄인다.
- **시그니처를 정하지 않고 시나리오부터** — 이름이 흔들리면 테스트 이름 · stub · 구현이 셋 다 흔들린다.
