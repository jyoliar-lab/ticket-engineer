# ticket-start — 착수·재개

낡은 코퍼스·오염된 브랜치 위에서 일하지 않기 위한 고정 순서다. 판단(티켓 이해·설계)은 네 것이고, 이 skill은 그 전에 밟을 바닥을 깐다.

## 절차

1. **티켓 읽기** — `gh issue view <N> -R jyoliar-lab/ops-workflow --comments`
2. **경계 추출** — 티켓에서 두 절을 **그대로 옮겨 적는다**(요약하지 않는다):
   - **완료의 모양** — 검수 기준이다. 그대로 `ticket-report`의 대조표 행이 된다.
   - **딸리지 않는 것** — 의도적 미결정 축이다. 작업 중 이 축에 닿으면 **멈추고 사람에게**(CLAUDE.md §3).
3. **근거 읽기** — 티켓이 링크한 ADR·discussion을 `workspace/ops-workflow/docs/`에서 읽는다. (코퍼스는 SessionStart hook가 세션 시작 시 최신화했다. 읽기 전용 — 저작 규약은 알 필요 없다.)
4. **저장소 정렬** — 판단하지 말고 스크립트를 돌린다:
   ```bash
   python3 "$CLAUDE_SKILL_DIR/scripts/ticket-run.py" <N> [--slug <slug>]
   ```
   착수(원격 브랜치 생성·Status 전환)와 재개(진행 보고·worktree 정렬)를 스크립트가 판별한다 — 원격이 진실의 원천이고, target 저장소마다 수행된다. **exit 코드가 다음 행동이다**:

   | exit | 뜻 | 네가 할 일 |
   |---|---|---|
   | 0 | 진행 | stdout의 상태(진행 커밋·PR·잔재 변경)를 읽고 작업 계속 |
   | 1 | 전제 거부 | 우회하지 않는다 — 사유(닫힘·컨테이너·target 없음·구식 티켓 등)를 사람에게 |
   | 2 | 승인 대기 | 원격 커밋과 로컬 미커밋 변경을 파악해 **처리 방안을 제안하고, 승인 후** 진행 |
   | 3 | 보고만 | 처리를 **시도하지 않는다** — 상태를 사람에게 보고하고 지시를 기다린다 |

   - `--slug`는 새 착수에만 필요하다(소문자 kebab 3–6단어).
   - target이 `(없음)`(신규 저장소 생성 작업)이면 exit 1 — 저장소 이름·위치·생성 방식을 **사람과 확인**한 뒤 진행한다.
   - 파괴적 정리(`reset --hard`·`stash drop`·강제 checkout)는 exit가 무엇이든 **하지 않는다.**
5. **작업 위치** — `workspace/<repo>/ticket-<N>/` (티켓별 worktree). 다른 티켓의 worktree·`workspace/.bare/`는 건드리지 않는다.
6. **착수 요약** — 경계 2절 + 스크립트가 보인 상태 + 이해한 작업 계획을 사용자에게 보인다. 계획이 티켓과 어긋날 소지가 보이면 진행 전에 묻는다.

## 뒷정리 — 사람이 close를 확인한 뒤에만

```bash
python3 "$CLAUDE_SKILL_DIR/scripts/ticket-clean.py" <N>
```
worktree·브랜치(로컬·원격)를 정리한다. 티켓이 열려 있거나, 미커밋 변경이 있거나, PR이 열려 있으면 **스크립트가 거부한다** — 우회하지 않는다. 자동 실행 금지 — 사람의 지시가 트리거다.

## 스크립트가 막으면

exit 1·2·3은 오류가 아니라 **경계 신호**다 — 위 표대로 행동한다. 강제로 상태를 맞추려 하지 않는다(reset·force 금지).
