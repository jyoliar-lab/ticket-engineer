# ticket-report — 완료 보고

보고 형식의 일관성이 곧 사람의 검수 비용이다. 기계가 확인할 수 있는 것은 스크립트가, 충족 여부의 **의미 판정은 네가** 한다.

## 절차

1. **preflight** — `preflight.py <N>` — **한 번의 실행이 티켓 스코프 전부를 검토한다**: 코멘트 전문을 보이고, 티켓의 target 목록↔worktree를 전수 대조하고, worktree마다 PR·참조·close 키워드·체크를 확인한다. (스킬 스크립트는 PATH에 있다 — 맨 이름으로 실행한다.)
   - 하나라도 실패면 **보고하지 않는다** — 무엇이 왜 막혔는지는 스크립트가 말한다. 해결 후 재실행. (막힌 것이 코드가 아니라 **티켓**일 수 있다 — 티켓 갱신은 사람과 합의해서. CLAUDE.md §3)
2. **대조표 작성** — 착수 때 추출한 **Acceptance Criteria 각 항목별로**: 항목 | 그룹 | 충족 방식 | 근거. PR 링크 포함 — **target 저장소별로 전부**. **근거의 종류는 AC 의 그룹이 정한다**:

   | 그룹 | 근거 |
   |---|---|
   | 동작 | 테스트 이름 — 대표 한둘 |
   | 검사 | 검사 명령 → 결과 한 줄(네가 돌린 것) |
   | 선언 | 선언 diff 의 위치 + 검증기 출력(스펙 lint · breaking-change · 코드 생성) |
   | 수렴 | 배포 뒤 명령 한 번 + 출력 — 코멘트에 그대로 |
   | 지속 | 창 끝 재확인의 날짜 + 지키는 알림 규칙. 창이 끝나기 전이면 ⚠(미확인 · 창 종료일) |

   - 충족 못 한 항목이 있으면 보고가 아니라 **사람과 논의**가 먼저다.
   - **코멘트도 경계다** — preflight가 보인 코멘트에 아직 반영하지 않은 요구·방향 수정이 있으면, 보고가 아니라 **사람과 논의**가 먼저다(위와 같은 취급). 반영한 것은 대조표에 근거와 함께 포함한다.
   - Requirements의 범위 밖 축에 닿았던 일이 있으면 그 경위를 명시한다(원칙은 닿기 전에 멈추는 것 — CLAUDE.md §3).
3. **게시** — `gh issue comment <N> -R jyoliar-lab/ops-workflow --body "..."` — **사전 승인 없이 게시한다.** 검수는 게시된 코멘트로 이루어진다. preflight 통과와 2단계의 항목별 대조가 게시의 전제 조건 전부다.
   - 성공 시 출력되는 코멘트 URL(`...#issuecomment-<id>`)의 **`<id>`를 기록해 둔다** — 수정은 이 ID로만 한다.
4. **게시 후 검수** — 사람이 게시된 코멘트를 읽고 검수한다. 수정 지시가 오면 새 코멘트를 달지 않고 3단계에서 기록한 ID로 **그 코멘트를 지정 수정**한다:
   `gh api -X PATCH repos/jyoliar-lab/ops-workflow/issues/comments/<id> -f body="..."`
   (`--edit-last`는 쓰지 않는다 — "내 마지막 코멘트"를 잡는 휴리스틱이라 보고 이후 다른 코멘트가 달리면 엉뚱한 것을 수정한다.)
5. **이후는 사람의 것** — 검수·머지·close. 재촉하지 않고 다음 지시를 기다린다.

## TDD 티켓이면 — 대조표는 verifier 의 것

착수 판정(`ticket-start` ⑥)이 `TDD: 대상` 이었던 티켓은 `tdd-loop` 가 이 절차의 앞을 대신한다: preflight 는 그 4단계에서 이미 돌았고, 대조표는 **`ac-verifier` subagent 가 단위마다 게시**했다(동작 · 검사 · 선언 AC — 단위 하나면 코멘트 하나). 2·3단계를 다시 하지 않는다 — 4단계(게시 후 검수 · 지정 수정)부터다. 예외는 verifier 가 ⚠ 로 남긴 **수렴 · 지속 AC** 다 — 배포 뒤 실측해 위 표의 근거로 코멘트 하나를 더 게시한다(2·3단계를 그 행들에만). 사람이 verifier 코멘트를 읽고 지시한 뒤에만 `gh pr ready` 로 Draft 를 푼다 — 지시 전에 풀지 않는다.

## preflight는 완료를 판정하지 않는다

스크립트가 통과해도 Acceptance Criteria가 충족됐는지는 별개다 — 그 판정은 2단계에서 네가 코드·동작을 근거로 한다. 애매하면 사용자에게 근거를 제시하고 묻는다.
